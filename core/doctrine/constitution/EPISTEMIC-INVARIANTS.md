# Epistemic Invariants

## Purpose

The Epistemic Invariants define the immutable laws governing Repository Intelligence.

They establish the relationship between Repository Information, Repository Knowledge, Repository Intelligence, Repository Wisdom, Repository Authority, and their manifestations.

All Repository Intelligence models, Repository Understanding models, Workspace agents, architectural decisions, implementations, and repository realizations SHALL preserve these invariants.

These invariants are constitutional.

They are independent of any particular repository domain, implementation technology, engineering discipline, or knowledge manifestation.

---

# Invariant 1 — Repository Authority

Repository Authority is the sole authority capable of establishing repository truth.

Repository Intelligence may inform Repository Authority.

Repository Wisdom may guide Repository Authority.

Neither Repository Intelligence nor Repository Wisdom establishes repository truth.

---

# Invariant 2 — Repository Information

Repository Information represents observed or recorded facts available to the repository.

Repository Information may be incomplete.

Repository Information may conflict.

Repository Information alone does not establish Repository Knowledge.

---

# Invariant 3 — Repository Knowledge

Repository Knowledge consists of durable knowledge manifestations representing repository truth accepted by Repository Authority.

Repository Knowledge is authoritative.

Repository Knowledge preserves its provenance.

---

# Invariant 4 — Repository Intelligence

Repository Intelligence is derived through reasoning over Repository Knowledge.

Repository Intelligence discovers relationships, patterns, implications, and synthesized understanding.

Repository Intelligence does not itself establish Repository Knowledge.

---

# Invariant 5 — Repository Wisdom

Repository Wisdom consists of judgments, recommendations, or courses of action derived from Repository Intelligence.

Repository Wisdom informs Repository Authority.

Repository Wisdom never replaces Repository Authority.

---

# Invariant 6 — Acceptance

Acceptance is the exclusive mechanism by which Repository Knowledge evolves.

Repository Intelligence may recommend acceptance.

Only Repository Authority performs acceptance.

---

# Invariant 7 — Provenance

Every transformation SHALL preserve provenance.

The origin of Repository Information, Repository Knowledge, Repository Intelligence, and Repository Wisdom SHALL remain observable throughout every governed transformation.

---

# Invariant 8 — Repository Understanding

Repository Understanding represents the repository's current accepted understanding of itself.

Repository Understanding is derived from Repository Knowledge.

Repository Understanding does not replace Repository Knowledge.

---

# Invariant 9 — Knowledge Manifestations

Repository Knowledge is communicated through Knowledge Manifestations.

Knowledge Manifestations are repository-specific realizations of Repository Knowledge.

Examples may include engineering artifacts, legal doctrine, medical protocols, operational guidance, educational material, or other repository-specific expressions.

Knowledge Manifestations communicate Repository Knowledge.

They do not establish Repository Knowledge.

---

# Invariant 10 — Realizations

Implementations, source code, generated artifacts, reports, visualizations, diagrams, workflows, runtime behavior, and other realizations communicate repository understanding.

Realizations SHALL be treated as evidence only when Repository Authority has accepted them as durable repository knowledge.

Realizations SHALL never establish repository understanding merely by existing.

---

# Invariant 11 — Reasoning

Reasoning SHALL distinguish:

- observed information;
- accepted knowledge;
- derived intelligence;
- recommended wisdom;
- accepted repository truth.

These epistemic states SHALL remain distinguishable throughout every governed transformation.

---

# Invariant 12 — Uncertainty

Where evidence is insufficient, uncertainty SHALL be preserved.

Unknowns SHALL NOT be replaced by assumptions.

Multiple supported interpretations SHALL remain distinguishable until Repository Authority resolves them.

---

# Invariant 13 — Domain Independence

These invariants apply independently of repository domain.

Repository Intelligence SHALL reason consistently whether the governed repository concerns software engineering, law, medicine, science, manufacturing, education, finance, or any other domain.

---

# Invariant 14 — Constitutional Supremacy

The Epistemic Invariants govern every Repository Intelligence activity.

Repository Intelligence Models, Repository Understanding Models, Workspace agents, architectural decisions, implementations, and knowledge manifestations SHALL remain consistent with these invariants.

Where inconsistency exists, these invariants prevail.

---

# Invariant 15 — Preservation

Repository Intelligence SHALL preserve epistemic distinctions.

Transformations SHALL NOT collapse Repository Information into Repository Knowledge, Repository Knowledge into Repository Intelligence, or Repository Intelligence into Repository Wisdom without the governed transformations defined by these invariants.
